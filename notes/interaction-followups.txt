Original complaints, in order
-----------------------------
1. Hooks take questions away from Codex (and potentially Claude).
   d4cd21b removes the blocking response bridge and installer setup, retaining
   observational hooks. The old entry point exits without reading a prompt or
   making a decision. Native agents own their content, choices and lifetime.
   The installed blocking hooks were disabled locally as well.

2. Phone / Live Activity can say Working while an approval is unanswered.
   The other report supplied a confirmed source repro, superseding the earlier
   decision to wait for a better repro. 1492c2f preserves approval attention
   across same-turn messages and unrelated tools, correlates matching tool
   completions without transmitting command text, and clears one matching
   approval at a time. Duplicate completions cannot consume identical siblings.
   d2e667e checks source state and outgoing Live Activity content after mobile
   expiry. Physical Live Activity rendering still requires a device repro.

3. Massive JSON makes Watch decisions impractical to reach.
   31a9e77 uses bounded excerpts, a compact field summary for unknown Watch JSON,
   and optional expansion. Full original input remains available and unchanged.
   There is no blanket removal of fields that merely look like display metadata.

4. Only Allow once appears; native choices may be missing.
   d4cd21b restores all decisions to the native UI. 31a9e77 adds ordered explicit
   choice IDs and labels to the v2 remote contract; only offered IDs are accepted.
   No active native-response adapter is enabled. Hook permission suggestions do
   not establish a complete native choice list, so no extra choice is invented.

5. Parsing relies on narrow text patterns.
   31a9e77 normalizes documented command, patch, Write and Edit schemas on the
   desktop. Unknown MCP input stays complete JSON. The v1 text compatibility
   decoder is separate from the new structured content path.

6. Decode at the right boundary; update the transfer protocol when needed.
   31a9e77 introduces contentVersion 2: typed action, reason, original input and
   explicit choices. Desktop decodes once; phone and Watch share Codable content.
   Capability negotiation excludes v2 from older clients; request identity and
   optimistic version remain separate from content version.

7. Show full should not look like a primary decision.
   9fcc11c makes Show more a leading text disclosure below the excerpt, with
   ellipsis and Show less when expanded. Hidden additional arguments have a
   distinct Show tool input disclosure. Native readable text sizing is retained.

8. Phone preview is too sparse.
   878ed9d shows a longer actual-input excerpt on iPhone with decisions pinned.
   The large simulator payload is synthetic. No semantic MCP summary is guessed.

9. Successive requests in one session require repeated row taps.
   4da142d keeps the selected session open and advances only after the exact
   current request receives confirmation. Arrivals do not replace a draft;
   uncertain replies retain their exact retry. It also fixes a confirmed Watch
   single-request read deleting sibling requests from the phone inbox.

10. Waiting sessions sit unnoticed; when should a question auto-present?
    4da142d automatically opens pending/next requests inside the selected session.
    Explicit Review can advance across sessions, with task/provider/computer
    context. Other sessions and ordinary app launch do not interrupt with a modal.
    Dismissal does not immediately reopen the same request.

Additional issues from the other report
---------------------------------------
11. write_stdin exposes raw controls and internal IDs.
    6caa07c distinguishes interrupt, poll and arbitrary input from Codex's native
    schema. Two actual Ctrl-C characters display as Ctrl-C × 2; literal escaped
    text is not decoded twice. A running command appears only with confirmed,
    matching adapter context. Original arguments remain available in full.

12. Native approval survives the ten-minute mobile deadline.
    Retiring interception removes the delay before native UI can present. Source
    attention is independent of a compatibility request's expiry/release.
    d2e667e verifies expiry cannot clear native attention or outgoing Live Activity
    counts. Why the phone first fetched late is still unknown from the evidence.

13. Could an accepted receipt hide another request?
    This was an audit question, not proof of the original source failure.
    d2e667e covers two approvals and approval/question pairs, either answer order,
    phone and Watch receipts, uncertain replies, duplicate receipts, delayed
    single-request reads and expiry of one request. Pending siblings take priority
    over a receipt in the shared phone/Watch presentation. Existing tests cover
    delayed full listings, exact retries and phone/Watch export consistency.

14. Review common agent concepts and their evolution boundaries.
    c451290 removes the provider whitelist from the common request contract while
    leaving provider enablement with adapters. Native schema interpretation is
    provider-scoped: another agent's tool named Bash is not assumed to be a shell.
    Wire envelopes project into validated content/action unions; mixed variants,
    missing fields, inconsistent terminal operations and unknown versions cannot
    expose decision controls. Terminal targets are opaque strings. Phone/Watch
    share question validation, including the server's selection-plus-comment
    semantics; question IDs use the same 160-character bound as the source.
    New provider launch labels fall back to a generic agent label.

    4d6d9d5 fixes a newly demonstrated fidelity bug: Swift Decimal rounds very
    large integers and rejects 1e300. Complete opaque input now travels as desktop-
    serialized inputJSON text, independently of structured typed actions. Clients
    preserve that text through round trips, without converting unknown numbers.
    Ingress still accepts a structured input value for proper desktop decoding.
    This refines the unreleased v2 contract; deployed v1 compatibility is retained.

    docs/agent-models.md defines session/activity/request/submission distinctions,
    adapter ownership and evolution rules. Current questions are a bounded legacy
    text/selection profile, not arbitrary native forms. Permission subsets, richer
    forms, secure inputs and URL flows need faithful new negotiated variants;
    unsupported semantics remain native. CodexAllowance stays explicitly Codex-
    specific instead of implying equivalent quotas for other providers.

    Latest checks: 193 Swift interaction/protocol tests and 36 targeted Python
    content/broker/HTTP/Watch tests passed; iPhone and Watch Debug builds passed.
    No product layout or installed source behavior changed in this model review.
